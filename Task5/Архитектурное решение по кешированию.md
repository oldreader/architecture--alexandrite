### Мотивация 
Для кэширования системы необходимо кешировать данные, 
которые возможно являются узким местом для клиента.
Будем исходить из гипотезы, что метрики показали нагрузку на БД и
проблемы получения данных со стороны MES API по заявкам. 
Для этого нам необходим механизм кеширования, который уберёт нагрузку на БД для чтения ордеров. 

### Предлагаемое решение 
1. Заявки обновляются со стороны разных акторов в системе, поэтому необходимо внедрять серверное кэширование. 
Для кэширования считаю необходимым использовать Write-Through и Read-Through шаблоны, 
так как мы хотим получать данные по ордерам, при этом не ходя в базу данных для MES API
и одновременно этот же кэш может быть использован CRM API, тем самым мы уберём задержку ожидания в Message Queue.
Если у нас случился hit-miss - мы просто будем ждать, когда данные дойдут по очереди до CRM. 
2. Инвалидация кэша: кэш инвалидируется по записи в БД MES API или в CRM API. 
Инвалидация по ключу - orderId. Для write и read сценариев инвалидация orderId будет справедлива, 
так как у нас не нужно вытеснять данные на первом этапе. Когда количество заказов будет расти, 
можно будет применить инвалидацию по времени, чтобы вытеснять старые заказы.
