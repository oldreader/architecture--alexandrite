Системы для логирования:
MES API, CRM API, SHOP API.
SHOP API:
- добавление заказа: Info, идентификатор заказа  
- редактирование объектов Сохранение: Info, идентификатор объекта  
- редактирование объектов Обновление: Info, идентификатор объекта

MES API: 
- запрос на расчёт: Info, идентификатор заказа
- извлечение из БД метаинформации: Info, идентификатор заказа
- извлечение из s3 объекта: Info, идентификатор заказа
- завершение извлечения из s3 объекта: Info, идентификатор заказа
- начало расчёта: Info, идентификатор заказа
- завершение расчёта: Info, идентификатор заказа
- отброс запроса в RabbitMq: Info, идентификатор заказа

CRM API:
- извлечение запроса из RabbitMq: Info, идентификатор заказа
- сохранение в БД магазина информации о заказе: Info, идентификатор заказа

Дополнительные кандидаты для логирования: 
- RabbitMS - системное логирование. Возможны какие-то ошибки сериализации: 
сообщения стали большие и не влазять больше в очередь. 
- Логирование базы данных: БД может сломаться по записе на диск или ошибки соединения реплик.
Мы сможем узнать, что есть тормоза, если сеть начинает моргать при записях на другие реплики. 

### Предлагаемое решение

Добавить логирование в первую очередь в порядке очереднсоти:
1. MES API - мы сразу сможем видеть проблемы в расчёте, так как там больше всего жалоб
2. CRM API - вторым шагом обновление информации для пользователя
3. SHOP API - логирование запросов от пользователей, чтобы видеть как они получают и видят информацию
Для чувствительных данных необходимо настроить filebeat процессоры, чтобы экранировать чувствительные данные в CRM API.
Логи необходимо хранить в Elasticsearch для дальнейшего анализа. Можно использовать один индекс для записи логов от приложений:
SHOP API, MES API, CRM API.
Для ротации индексов необходимо настроить ILM на ротацию индекса по размеру и снижения тира старых данных. Наиболее полезным видится ротация оп времени.
Старые логи можно отправлять в холодные тир данных. Удаление логов можно согласовать с требование регулятора: пользователь может вернуться с претензией.

### Алертинг

Реализовать алертинг для сучаев: 
1) Ошибки в калькуляции рассчета заказа в MES API. Это покажет, что заказы просто никогда не обновятся.
2) Алерты, если есть разница в сумме записей в очередь из MES API и чтения из очереди в CRM API.
